The throughline

Two of these already run on your infrastructure.

Baadh Mitra takes the severity levels behind Google's Flood Hub and asks the question the forecast alone can't answer: once the river's rise is predicted correctly, who actually knocks on the door first. DoorStep takes Google's own Plus Codes, already free and open, and adds the one layer they don't carry by themselves: a reason to trust the code a stranger just handed you.

Neither project is affiliated with or endorsed by Google. Both are an honest attempt to sit on top of what's already open and finish the last mile it doesn't reach. Riskky and Trustly, the other two, aren't built on Google's tools, but they share the same instinct: every score explains itself, and nothing ships without the reason attached.

Baadh Mitra - Flood Relay Coordinator

FastAPIReactPostgreSQLSQLAlchemy
Live ↗ GitHub ↗
Problem

Google's Flood Hub can forecast river levels up to seven days ahead for hundreds of millions of people. In places without direct smartphone reach, someone still has to walk door to door and decide, from memory, whose house to reach first.

Approach

Baadh Mitra turns a district's household roster into a ranked, explainable checklist. Seven weighted factors, elevation, elderly only status, smartphone access, mobility, household size, get scored against the active alert and recalculated fresh every time severity changes. Every ranked entry keeps its reasons attached, riverbank, elderly only household, no resident smartphone, so a volunteer moving fast can trust the order at a glance instead of guessing.

Detail

Alerts come from a simulated Flood Hub style gauge feed, written so a real feed could be dropped in behind the same function signature. Backend and frontend deploy independently, connected only over HTTPS with their own CORS boundary.

Independent project. Not affiliated with or endorsed by Google.

DoorStep - Trust Network

FastAPIReactSQLite / Postgresopenlocationcode
Live ↗ GitHub ↗
Problem

Roughly 68 percent of India lives where formal street addresses don't exist. Google's Plus Codes solve the coordinate problem, a short, shareable code for any location, but the code alone carries no signal of whether it's current, accurate, or actually tied to the household it claims.

Approach

A household registers a real Plus Code, validated server side against Google's own openlocationcode library. Neighbours who actually know that household add a vouch, and each vouch raises a transparent trust tier from New to Highly Trusted, visible to a delivery rider or ambulance dispatcher before they travel there.

Detail

A printable marker with a QR code makes the doorstep discoverable offline, and a simulated SMS path shows the same lookup working over a basic phone with no data connection at all.

Independent project. Not affiliated with or endorsed by Google.

03 · Personal project · Apr-May 2026

Riskky - UPI Risk Companion

FastAPIReactScikit-learn
Live ↗ GitHub ↗
Problem

Government fraud signals flag risky phone numbers but say nothing about what a specific transaction looks like in context. A collect request disguised as a refund, or a QR code with a mismatched amount, succeeds in that gap, especially for someone not comfortable reading fast, English heavy financial jargon.

Approach

Riskky runs a transaction through ten explainable rules, written from documented UPI scam patterns, blended with a logistic regression classifier. It returns a risk score, the specific patterns matched, and a plain language explanation read aloud in the user's own language, right at the screen where a PIN would be entered.

Detail

Flagged transactions carry a short cooling off period, and the button to override that warning was deliberately kept off the brand's primary colour, so overriding a warning never looks like the rewarded choice. The classifier trains on synthetic data, stated directly in the project rather than glossed over.

04 · Personal project · May-Jun 2026

Trustly - Neighbourhood Trust Score

FastAPIReactPytestGitHub Actions
Live ↗ GitHub ↗
Problem

A star rating alone hides a lot. A one line review with no detail counts the same as a thoughtful one, and a burst of near identical five star reviews posted within hours reads the same as five reviews earned naturally over a year.

Approach

Trustly runs four independent, fully documented checks against reviews pasted in by hand: generic text, rating and text mismatches, clustered posting times, anonymous reviewer names. Each flag carries a fixed penalty, and the API returns which specific rule triggered on each review, not just a final number.

Detail

Nothing here is machine learning, every number is a fixed rule in one file, and the backend is covered by an automated Pytest suite that runs on every push through GitHub Actions.
